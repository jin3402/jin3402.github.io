> CORS·스냅샷·광고·프로모션·콘텐츠 필터까지, **미니앱 실서비스 제약을 뚫으면서** 할인 게임 큐레이션 제품을 끝까지 만든 프로젝트입니다.

- **GitHub:** [jin3402/gamsale](https://github.com/jin3402/gamsale)
- **플랫폼:** Apps in Toss WebView · TDS
- **역할:** 개인 / 기획·개발·배포 전반

## 문제 정의

게임 할인은 Steam, Epic, Xbox, PlayStation, Nintendo에 흩어져 있습니다. 한곳에 모아 보여주면 쓸모 있는 서비스가 되지만, 토스 미니앱 WebView에서는 외부 스토어 API가 **CORS로 막히는 경우**가 많습니다.

동시에 만족해야 하는 조건도 많았습니다.

- TDS(Toss Design System) UI
- 광고 정책과 전면/배너 광고 연동
- 프로모션 검수
- 선정성 콘텐츠 기준

일반 웹처럼 `fetch`만 호출해서는 출시까지 갈 수 없는 환경이었습니다.

## 해결 방향

| 영역 | 접근 |
|------|------|
| 데이터 | Steam/Epic은 CheapShark 실시간 API, 콘솔은 빌드 타임 스냅샷 + 런타임 폴백 |
| UX | TDS 카드 UI, 플랫폼 필터, 위시리스트, 게임 탭 시 액션시트 |
| 수익화 | 배너 광고 + 스토어 이동 전 전면형 광고 |
| 성장 | 앱 진입 시 프로모션 포인트 지급(기기당 1회) |
| 안전 | 닌텐도 성인·선정성·저품질 타이틀 필터 |

## 왜 스냅샷인가

개발 서버(Vite 프록시)에서는 Nintendo / PlayStation / Xbox 스토어를 실시간으로 부를 수 있습니다. 하지만 운영 WebView에서는 CORS 때문에 같은 요청이 실패합니다.

그래서 **빌드 시점(`npm run prebuild`)에 Node에서 목록을 받아 TypeScript 스냅샷으로 넣고**, 운영 앱은 그 스냅샷을 보여줍니다. 스냅샷 생성이 실패하면 이전 스냅샷을 유지해 빈 화면을 피합니다.

```text
[토스 미니앱 WebView]
        │
        ├─ Steam / Epic  ──► CheapShark (CORS 허용, 실시간)
        │
        ├─ Xbox / PS / Nintendo
        │     ├─ 개발: Vite 프록시로 실시간 가능
        │     └─ 운영: prebuild 스냅샷 번들 → 런타임 사용
        │
        ├─ 광고 ──► load/showFullScreenAd, TossAds Banner
        └─ 프로모션 ──► grantPromotionReward (진입 시 1회)
```

## 주요 기능

### 멀티 플랫폼 할인 목록

Steam / Epic / Xbox / PlayStation / Nintendo Switch / 전체 탭으로 나눕니다. 할인율·가격·썸네일을 카드로 보여주고, 세션 단위로 상위 노출을 셔플해 매번 같은 게임이 맨 위에 나오지 않게 했습니다.

### 부하를 줄인 더보기

처음부터 전체를 받지 않습니다. 초기에는 약 150개만 로드하고, 이미 받아둔 목록을 다 본 뒤에만 Steam/Epic 다음 페이지를 추가 fetch 합니다. API와 번들 부하를 동시에 줄이기 위한 선택입니다.

### 액션시트와 광고 타이밍

카드를 누르면 **스토어에서 보기 / 공유하기**가 나옵니다. 전면 광고는 탭 전환마다 띄우지 않고, **스토어로 이동할 때만** 보여줍니다. 하트(찜)는 카드와 분리해 광고와 무관하게 동작합니다.

### 프로모션과 콘텐츠 안전

앱 진입 시 토스 포인트를 기기당 1회만 지급합니다. 닌텐도 목록은 스냅샷 생성 시점과 런타임에 키워드 필터를 이중으로 적용해 선정성 타이틀이 노출되지 않게 했습니다.

## 기술 스택

- Language / UI: TypeScript, React 18, Vite
- Platform: `@apps-in-toss/web-framework`
- Design System: `@toss/tds-mobile`
- Data: CheapShark, PlayStation GraphQL, Xbox Store Edge, Nintendo KR Store
- Ops: `prebuild` 스냅샷, `.ait` 번들 배포

## 개발하며 겪은 이슈

| 이슈 | 결정 |
|------|------|
| 콘솔 스토어 CORS | 빌드 타임 스냅샷 + 이전 스냅샷 폴백 |
| 상위 게임이 항상 같음 | 할인율 상위 풀을 세션 시드로 셔플 |
| 탭 전환마다 광고 | 스토어 이동 시에만 전면 광고 |
| 리스트를 무한으로 늘리고 싶음 | 150개 이후 Steam/Epic만 페이지 단위 로드 |
| 닌텐도 선정성 타이틀 | 스냅샷/런타임 이중 필터 |
| 미니앱 이름 반려 | 콘솔 등록명과 `brand.displayName`을 동일하게 맞춤 |

## 마치며

이 프로젝트에서 배운 것은 API를 많이 붙이는 일이 아니라, **플랫폼이 허용하는 범위 안에서 제품을 완성하는 일**이었습니다. WebView 제약을 핑계로 기능을 줄이지 않고, 스냅샷·폴백·필터·광고 타이밍으로 출시 가능한 형태까지 가져간 기록이기도 합니다.
