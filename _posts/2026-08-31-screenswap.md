> Mission Control이 하는 "모든 창을 새 위치에 실시간으로 그려서 보여주는" 동작은 비공개 API 영역이라 서드파티 앱은 쓸 수 없습니다. 대신 진짜 창을 Accessibility API로 직접 옮겨서, 화면에 보이는 게 스크린샷이 아니라 항상 살아있는 창이게 만들었습니다.

- **GitHub:** [jin3402/ScreenSwap](https://github.com/jin3402/ScreenSwap)
- **플랫폼:** macOS 14+ · Swift, AppKit, Accessibility API
- **역할:** 개인 / 기획·개발 전반

맥북 화면 하나와 외부 모니터 하나를 같이 쓰면, 창이 지금 어느 쪽에 있는지 헷갈리고 겹친 창 중 하나를 골라내기가 번거로워집니다. Rectangle 같은 도구는 "지금 이 창"을 어떻게 배치할지에 집중하고, AltTab·Witch 같은 창 스위처는 "창 하나를 골라 활성화"하는 데 집중합니다. ScreenSwap은 그 사이 — 두 화면에 걸친 여러 창을 한 번에 고르고 옮기는 문제를 풉니다.

## 1. 단축키 하나로 시작하는 오버레이

⌃⌥↑ 를 누르면 화면 전체에 오버레이가 뜹니다. 방향키로 포커스만 옮기고(이 단계에서는 창이 전혀 움직이지 않습니다), Shift를 탭해서 선택한 다음, 어떻게 할지(전송·분할·전체화면·종료)를 정합니다. "조준"과 "실행"을 분리한 게 핵심 설계입니다 — 초기 버전은 Shift를 떼는 순간 바로 창이 날아가서, 고르다가 실수로 옮기는 일이 잦았습니다.

## 2. 스크린샷이 아니라 진짜 창을 옮긴다

Mission Control은 윈도우 서버 안에서 모든 창의 실시간 텍스처를 새 위치에 그려서 보여줍니다. 서드파티 앱이 쓸 수 있는 방법은 두 가지뿐입니다 — 창을 캡처해서 정지 이미지로 펼치거나(Witch·AltTab이 쓰는 방식), 진짜 창을 Accessibility API로 옮기거나. ScreenSwap은 후자를 택했습니다. 오버레이를 열면 겹친 창들이 실제로 움직여서 펼쳐지고, 어떻게 닫든(esc, 액션 실행, 다른 앱 클릭) 원래 자리로 정확히 되돌아갑니다.

대가도 있습니다. 창을 줄이면 에디터는 사이드바를 접고 브라우저는 레이아웃을 다시 흘립니다. 원래 크기로 되돌리면 레이아웃은 복구되지만 스크롤 위치 같은 세부 상태까진 완벽히 안 돌아올 수 있습니다. 창이 열 개가 넘어가면 펼치는 데 한 박자 걸립니다. 대신 화면에 있는 건 항상 진짜 창입니다. 앱이 도중에 죽어도 안전하도록, 펼치기 전 원래 위치를 디스크에 먼저 적어 두고, 다음 실행 때 복구를 제안합니다.

## 3. 여러 창을 골라 한 번에 처리하기

Shift를 탭할 때마다 포커스된 창이 선택 목록에 쌓입니다 — 파일 목록에서 Shift+화살표로 범위를 넓혀가는 것과 같은 느낌입니다. 선택한 다음에는:

- **⌘ + 방향키** — 선택한 창 전부를 그 방향 모니터로 전송
- **⌘2 / ⌘3 / ⌘4** — 겹친 창들을 2·3·4분할로 그 자리에서 배치 (4개 넘으면 마지막 칸에 겹쳐 쌓임)
- **Enter / ⌫** — 전체화면 진입 / 해제
- **⌘Q** — 선택한 창들의 앱 종료 (실제 ⌘Q와 동일한 요청이라 저장 안 한 문서가 있으면 그대로 저장 시트가 뜹니다)
- **space** — 두 모니터의 창을 통째로 맞바꾸기. 겹쳐 있던 그룹은 반대편에서 자동으로 분할 배치됩니다
- **⌘Z** — 방금 한 이동을 되돌리기

## 구현 중 막힌 지점

| 이슈 | 원인 | 해결 |
|------|------|------|
| 방향키가 전혀 반응하지 않음 | macOS가 방향키에 항상 `.function` 플래그를 붙이는데, "다른 모디파이어 없음" 검사가 전체 플래그와 비교되면서 걸러짐 | shift/control/option/command 네 개만 마스킹해서 비교 |
| 오버레이가 보조 모니터엔 아예 안 뜸 | AppKit이 메뉴바를 가리는 창 프레임을 자동으로 밀어내리는데(`constrainFrameRect`), 보조 디스플레이 패널이 매번 밀려남 | `constrainFrameRect`를 오버라이드해서 그대로 통과시킴 |
| 좌우로 나란한 두 모니터인데 ↓ 방향키가 반대쪽 모니터로 판정됨 | 두 모니터 높이가 달라 중심 y가 몇 px 차이나는 것만으로 방향 판정 로직이 반응 | 요청한 축의 변위가 수직 변위보다 커야만 그 방향으로 인정하도록 조건 추가 |
| 창이 여러 개인 앱에서 스왑하면 일부가 조용히 안 옮겨짐 | CG 창을 AX 엘리먼트에 하나씩 매칭하다 보니, 같은 앱의 여러 CG 창이 같은 AX 엘리먼트를 두고 경쟁해 나머지는 매칭 실패 | 프로세스 단위로 CG 창–AX 엘리먼트를 일괄 배정하도록 매칭 로직 재작성 |
| ⌘2/3/4 분할이 보조 모니터에서 안 먹힘 | 선택 없이 분할할 때 "어느 화면"을 조준 커서 기준으로 골랐는데, 커서는 오버레이를 열기 전 활성 앱이 있던 화면에서 시작함 | 화면 전체를 대상으로 하는 액션은 마우스가 있는 화면을 우선하도록 변경 |
| Tab으로 창을 앞으로 가져와도 일부 앱은 실제로 안 뜸 | Electron 기반 앱 등은 `AXRaise` 액션만으로 내부 창 순서가 안 바뀌는 경우가 있음 | `AXMain` / `AXFocused` 속성도 함께 설정 |

## 기술 스택

- Swift, AppKit
- Accessibility API (`AXUIElement`) — 창 목록 읽기, 이동, 포커스 전환
- Carbon Hot Key API — 시스템 전역 단축키
- 로컬라이제이션(한국어/영어), `SMAppService` 기반 로그인 시 자동 실행

## 마치며

이 프로젝트에서 제일 오래 걸린 부분은 "창을 옮기는 코드" 자체가 아니라 **AppKit과 CoreGraphics, 두 좌표계를 안 섞이게 하는 것**이었습니다. 하나는 원점이 왼쪽 아래고 위로 갈수록 값이 커지고, 다른 하나는 원점이 왼쪽 위고 아래로 갈수록 값이 커집니다. 모니터가 나란히 있는지 위아래로 있는지, 보조 디스플레이의 원점이 음수인지까지 매번 확인해야 했고, 위 표에 있는 버그 대부분이 거기서 나왔습니다.
